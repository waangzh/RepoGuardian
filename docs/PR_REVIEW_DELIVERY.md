# PR Review 输出与交付

本实现依据《PR Review 输出与交付体系改造方案》，优先落地 P0-A、P0-B 与 P1 的本地发布契约。保留现有只读审查、Sticky Summary、COMMENT 型 Inline Review、权限预检、快照校验、发送意图与远端回执对账。

## 生成流程

1. 新任务的 `task_runtime_configuration.output_policy` 冻结展示开关、摘要开关、中文语言、输入上限、输出 token、子预算与时限。旧任务缺少该字段时继续使用原有输出。
2. `task_review_v1` 完成核心审查、独立核验并保存权威事实后，`ReviewService` 调用独立 `freeze_review_synthesis()` 阶段。
3. 事实包只读取已经保存的 PR 元信息、可读且非敏感变更 hunk、已准入 Finding 和绑定观察，不读取额外源码或私密讨论。作者文本属于不可信声明。每个来源都有稳定引用；省略文件/hunk 和输入截断明确记录。
4. 摘要工件使用既有 `side_effects` 表独立保存，包含 Review、Head、有效 Base、事实包哈希、来源策略和提示词版本。单 Review 的唯一 claim 在发送前持久化，崩溃、取消、重复执行均不自动补发。
5. 模型调用复用 Provider 的 JSON、模型窗口准入和 `ReviewRunBudget`，使用独立 `synthesis:<review_id>` 子预算，最多一次传输。预算变更有 CAS、任务生命周期与 worker lease 校验，不修改主审查账本和核验完成状态。
6. 严格 Schema 拒绝额外字段；校验引用类型、Finding 白名单、重复键及危险内容。测试源码不等于测试执行；严重度、统计、动态验证和合并建议由原有 Facts 决定。模型失效、输入不足、无预算或超时时冻结确定性回退。
7. `PublicationPlanner` 仅读取冻结工件，重新核对身份与事实包哈希，生成 `ReviewPresentation`。打开报告、切换密度、复制、重复预检均不会调用模型。

`ReviewSynthesisDraft` 中的段落采用 `{text, source_refs}`，使整体变更概述和审查总结也有来源约束。编辑性 Finding 摘要保存在工件中；公开问题的核心主张、定位和建议仍使用原核验文本。

## 交付流程

- Summary 按“本次 PR 主要变更 → 审查结果 → 实质限制/未决调查 → 验证与合并建议”组织。行内问题只显示短索引；无法定位的问题保留完整问题、触发影响和建议。
- “本次 PR 主要变更”统一为一段概述：优先使用有效冻结摘要；确定性回退选取已有实现与测试源码观察，不再展开旧版目标、实现和测试核对结构。已有实现概述时不重复追加作者目标；只有作者目标时明确其声明性质与实现观察缺口。缺失观察不作为有效内容，只有变更元数据时保留元数据边界；测试源码观察不代表测试执行。
- 默认概述以 2–4 句为目标，资料不足时不补写凑句；补充测试观察只在剩余句数内整条选取，已有概述的条件、否定和必要边界不因凑句数而删除。审查结果先给一句结论，再列问题；常规发布统计与额外编辑总结保留在详细模式，部分选择、被扣留问题和未决风险仍明确披露。验证与建议只列已保存的范围、动态验证状态和必要动作，不固定追加未获取 CI 的通用提醒；没有目标记录时范围保持未知。
- 未决调查只投影为一组“待核实事项”，逐项列出调查对象、当前疑点、缺少的证据和建议动作；对应的通用 investigation 限制不再重复出现。调查仍保持 unresolved，不进入 Finding 准入、严重度或已确认问题计数；完整命题、请求范围、行号和运行证据留在内部技术审计记录。
- 主结论分别表达已确认代码问题与审查完整性；“未发现已确认问题”只在权威 Finding 状态允许时使用，失败、取消、未知状态和已核验历史风险继续优先显示。
- 摘要输入的作者上下文截断、Diff 片段截断/遗漏、来源容量限制、审查范围排除、敏感/二进制排除和非法路径分别记录。只有 Diff 片段实际截断或遗漏时，公开概述提示覆盖受限，并明确这不代表静态审查范围不完整；内部技术审计保留原因与遗漏计数。旧 v1 摘要工件继续按旧事实包哈希绑定，覆盖原因由同快照资料确定性派生。
- 复制评论来自同一个 Presentation，展开每项完整正文和固定源码位置，明确只复制文本，不创建 GitHub Inline 线程。简洁/详细及人工处理筛选沿用现有服务端预览和稳定正文确认。
- 发布前保留独立授权、PR 身份、权限、Head/Base 和精确 Diff 映射。预检展示确认数、可交付数、选中数、Summary-only、已有线程和未选择数。未获取远端回执的 `actual_published` 为 `null`。
- 发布仍先落库意图，再更新 Sticky Summary、批量发布 Inline、对账回执并回填真实讨论 URL。只有 Summary-only 时不创建空 Review。
- 未选择的高优先级问题不会改变全局合并建议；部分发布继续要求原有显式确认。未知投递不自动重发；远端人工修改、错误身份和过期快照继续拒绝。

## 兼容与去重

不新增数据库表或列，因此无需 Alembic schema 迁移。独立工件复用现有带任务外键的 `side_effects` JSON 记录，任务删除沿用现有清理边界。主审查聚合读模型将摘要用量加入 `model_usages` 和 `model_usage_summary`，通过已有任务接口查询，同一 ID 不重复累计；未知用量和费用保留 missing。

新 `PublicationPlan` 的可选 `presentation` 进入 Plan Hash；缺失时不参与序列化，旧冻结计划维持相同哈希和正文。轻量 Summary 只返回 Presentation 元信息，不携带逐条正文。选择和内容变化仍要求重新预检。

新 Inline 简化可见正文，但保存 `legacy_body_markdown` 并使用原正文计算既有 fingerprint。远端读取只接受同一发布者、快照、锚点、Review 批次身份下的“完整旧正文”或“完整新正文”；不因措辞变化重新创建线程，也不接受被任意修改的远端正文。

如果摘要生成期间已有发布意图冻结，工件继续使用回退正文，不替换已经确认的发布内容。只完成只读预检时生成结果可能随后可用，此时 Plan Hash 变化，发布会拒绝旧确认并要求重新预检。

## 配置与回滚

配置项见根目录 `.env.example`：

| 配置 | 默认值 | 含义 |
| --- | --- | --- |
| `REPOGUARDIAN_REVIEW_PRESENTATION_V1_ENABLED` | `true` | 新任务使用结构化双层输出 |
| `REPOGUARDIAN_REVIEW_SYNTHESIS_ENABLED` | `true` | 新任务默认启用额外的模型编辑调用；可显式关闭 |
| `REPOGUARDIAN_REVIEW_SYNTHESIS_MAX_INPUT_CHARS` | `24000` | 事实包硬字符上限，超限回退 |
| `REPOGUARDIAN_REVIEW_SYNTHESIS_MAX_TOKENS` | `16000` | 独立摘要输入/输出累计 token 上限 |
| `REPOGUARDIAN_REVIEW_SYNTHESIS_OUTPUT_TOKENS` | `1800` | 单次输出 token 上限 |
| `REPOGUARDIAN_REVIEW_SYNTHESIS_TIMEOUT_SECONDS` | `20` | 摘要阶段超时 |
| `REPOGUARDIAN_REVIEW_SYNTHESIS_MAX_COST_MICROUSD` | 未设置 | 可选费用硬上限；价格缺失时拒绝调用 |

关闭摘要开关后，新任务使用确定性回退；关闭展示开关后，新任务使用原输出。任务策略冻结，不根据后续配置改写已保存任务或已经发布的 GitHub 评论。没有自动批量删除、重生成或重新发布功能。

## 验证与上线边界

聚焦回归覆盖双层渲染、部分选择、定位回退、旧哈希、单次摘要、引用/Schema 拒绝、输入截断、敏感路径、未知用量、并发 claim 及原有发布恢复。前端检查结构化来源、计数和旧格式兼容，运行测试及类型构建。测试使用受控模型响应，不产生付费请求。

确定性校验能拒绝越权字段、非法引用和明显的验证/合并断言，不能证明自由文本对代码的所有语义解释。新任务默认启用模型摘要，已有环境变量和冻结策略继续优先；如需关闭额外模型调用，可显式设置 `REPOGUARDIAN_REVIEW_SYNTHESIS_ENABLED=false`。默认启用不代表已经完成真实 PR 黄金样例验收，仍需人工核对其忠实性。

尚待外部验收：授权测试仓库上的真实 GitHub 发布、折叠/排列、跨版本线程复用与回执链接检查；人工黄金样例签收。未进行真实 GitHub 写入或付费模型调用时，不能以本地合成测试替代这些结果。

P2 的英文/自动语言策略和质量指标评测仍为后续工作，首版中文；严重度继续显示权威原值，不在未经产品确认时启用 P0–P3 映射。原生单 Review 模式维持非首版范围。
