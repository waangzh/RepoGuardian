# P5 后续：冻结审查契约与单样本核验

前一阶段 `e974a77` 保留了 P5 筛选失败：v7 首样本虽然所有范围被接受为 examined，但零候选，遗漏独立历史盲审认可的缺陷。默认保持 `legacy_units`，整体改造未完成。

## 本次变更边界

旧协议的业务示例仅有 examined 与空 candidates，提示内容以 schema 展示为主，未明确检查完成与缺陷报告可以同时存在。新的 `task-review-prompt-v2` 以审查契约说明 inspect / investigate / verify 的责任；不提供某个评测缺陷、参考意见、库函数答案或针对样本的规则。inspect 要比较旧新实际操作与具体触发条件，生成可独立验证的候选；examined 仅记录已做分析，不能解释为无缺陷。调查与验证分别保留反驳和缺证语义。

v2 的 schema 仍由同一 Pydantic 模型生成，只去除 title/description/default 展示元数据，保留 required、限制、互斥种类与拒绝额外字段。解析器和安全验收不放宽。说明字段要求简体中文，源码引用保持原样。

新任务创建时冻结 prompt_version；没有该字段的旧配置继续 v1，检查点维持旧 spec 的兼容序列化。v2 检查点明确绑定版本，恢复时版本变化拒绝，不因为部署更新静默切换 Prompt。

## 验证与实验预算

先验证新旧 schema 校验一致、同一提交同时接受 examinations 与 candidates、旧版本 Prompt 保留、未知版本拒绝、恢复版本变更不发请求，再执行后端回归与 Ruff。

本次真实核验仅计划一个 ComfyUI 首样本，使用新的清单和目录，固定原模型/provider、SHA、diff、权限和实际窗口，保持 `protocol_180`、单请求 60 秒/两次尝试、样本 1800 秒、200 次 wire/100 万 tokens 上限。不使用已知缺陷引导模型，不更换模型，不自动重跑相同实现。是否扩展仍需接入门、独立质量门同时成立；该样本的有效独立缺陷不减少只是开发门，不能证明泛化。旧尝试费用继续累计，禁止覆盖。

v8 使用 prompt-v2，真实 6 次 wire / 48,391 tokens，账本 complete，接入门失败。首轮已生成具体掩码缺陷主张，但顶层返回 type 而非 kind、primary_anchor 返回源码/行号，纠错后仍未符合 schema，合法检查均未接受。未扩展余下样本。该输出未经独立质量验收，不能计算有效缺陷数量。

根据这个格式失败另立 `task-review-prompt-v3`，保留 v2 已创建任务的原模板，v3 恢复仍绑定独立版本。给出仅含占位说明的候选/检查结构示例，primary_anchor 绑定实际 goal_id；Prompt schema 显式要求 kind，并将目标 ID 可选值限定到服务端当前目标。实际响应验收仍使用原 schema 与服务端身份检查，不接受 type、包装字段或源码形式的 primary_anchor。

新旧模板和恢复检查 77 项通过，v2 全后端 1208 passed、2 skipped，Ruff 通过。v3 只做一次新的首样本核验，保持之前同样上限，v8 费用保留，未在相同实现上付费重复试验。

v9 使用 prompt-v3，5 次 wire / 33,539 tokens，一次真实搜索，账本 complete；接入门仍失败。模型生成了两条候选，包括具体掩码缺陷，但 examinations 漏传 evidence_ids，被完整范围验收拒绝；有效候选引用整段超过8000字符，Policy 保留 unresolved；另一条死代码主张被搜索找到调用方，但验证结果未包含所有必要原证据，仍被拒绝。候选识别、证据就绪、独立确认分别记录，不能将发现主张当质量已通过。

根据这一可复现边界另冻结 `task-review-prompt-v4`：初始固定原文同受控工具原文一样切为80行/4000字符的规范证据块，每块原文/范围/hash一致，完整目标仍一次分母，容量分页能从块集重建原文并拒绝缺口/冲突。候选可以只引用支撑缺陷的小块，examined 必须引用覆盖完整范围的块集。Prompt 显式要求 examinations/investigation/verification 的 evidence_ids，验证 supported/refuted 必须包含必要原证据及新反证。服务端既有验收不放宽，不自动补证据引用。v1/v2/v3 已创建任务继续各自原模板与证据粒度。

v4 本轮仅离线验证，不再追加付费重试。两次真实尝试共11次 / 81,930 tokens；累加前一阶段后P5共149次 / 971,547 tokens。后四个及其他组均未派发，默认仍旧引擎，联合验收未通过。

## v4 离线修复与回归

端到端回归暴露容量分页会重新合并小块原文，造成超过4000字符的候选锚点。分页现在把完整页范围与页内证据块分别保存：完整范围继续属于同一个检查目标，页内证据复用80行/4000字符切块，不再因页容量较大而生成大锚点。多块重建拒绝正文hash不符、声明行数不符、缺失行及冲突行。

另一个可复现问题是派生验证任务激活同文件全部归档原文，重复携带初始证据与分页证据。v4验证改为只激活服务端绑定的必要证据和已知反证；其他证据仍留在Evidence Store，必要时通过受控取证进入当前请求。v1/v2/v3任务保留原可见证据选择。证据身份、引用校验和supported/refuted验收不放宽。

新增178行大范围回归，在SDK stub下完成多页检查、小块候选、一次独立验证及同一运行账本对账；测试专用额度20次、期限60秒只为覆盖完整调用链，不更改真实实验冻结额度。该结果证明路径连通，不证明模型审查质量。协议、生产接入、分页、恢复和调查/验证共68项聚焦回归通过，完整后端回归1212 passed、2 skipped（245.25秒），Ruff与git diff --check通过。
