## 版本与证据

初版冻结 review-stability-v1；旧配置缺省关闭，序列化不向旧 Spec 补字段。v7 关系规划器沿用 import-evidence-v5，通过具体调用方收集有限的已解析直接调用定义，包含嵌套调用的外层实现。不同调用命题保留各自关系成员；本次不以相同取证范围为由合并不同命题。后续 v8 收紧规则见下文。

预装载以固定快照和既有受控读取实现：优先必要调查范围，再补充被修改符号及直接定义，稳定排序、有界分块。归档原文可在快照、内容和路径校验后成为活动证据；定义提示和搜索命中摘要不作为实现证据。必要证据缺失时不得确认完整调用链。

模型可返回结构化 missing_evidence。服务端校验路径、范围、容量与次数，读取新证据后重开同一调查；拒绝、重复或无进展时保留不足。每次只读与模型提交沿用预算、取消、期限和 checkpoint。补读计数与请求范围持久化，恢复不重复发送。

## 完整性与资源

初始目标覆盖、必要调查和可选关系提示分别保留。只有未升级为必要义务的提示可以不阻断结论；不根据问题数量、模型置信度或预算不足把必要义务降级。

根据可用调用数与当前未完成工作项数，以及下一请求的输入输出预留估算，进入只提交模式并停止新增模型探索；多并发仍由共享账本准入，不创建私有计数器，也不承诺每个 Unit 一定有额外收尾额度。最终提交仍经过相同证据校验；新候选若无核验资源保持未决。没有资源或原期限已到时保留真实终止原因。

新契约使用低温度并将实际参数绑定请求哈希。旧任务的默认参数不变；不发送未经确认支持的 seed。

## 恢复与复用

已有 Provider 传输重试继续是唯一传输重试层，不再叠加盲目重试。先重放持久化响应；已发送但未知的消费和结果保持未知。显式目标恢复扩展到有界的必要调查缺口，仍保留已验收兄弟目标、原预算、纠错次数和期限。

同 Head 的结果复用仅在预览请求显式提供 `reuse_review_id` 时进入，要求相同 Base/Head、PR 背景、规则、模型、端点、采样、协议、计划、依赖和计量。旧绿色记录不能作为新契约成功种子。普通新审查不隐式命中结果缓存。新 Head 的增量复用沿用原保守边界。

## 验证与回退

使用真实 Provider 发送边界的 SDK stub、临时 Git 快照与 checkpoint 回归。验证成功、拒绝、容量、取消、预算、重放、部分恢复和旧输入身份。用历史产物离线重建关系规划，不调用模型、不写业务库。

契约缺省关闭可回到旧行为，已创建任务继续按冻结值运行。无数据库列变更；新增内部字段仅保存在现有 JSON 快照和工件。

## 漏引与调用范围修正

任务 cd27c7ec 的两个初始目标均已验收，11 项调查中一项因两次漏引已读的 family_wise_z 实现失败。v7 把同一调用方全部直接实现当作必要证据，使另一条独立断言也阻断当前 weighted_posterior 命题。

新任务冻结 risk-planner-v8 / import-evidence-v6。Python 调用索引保留表达式起止位置，新图按调用位置的包含关系选取嵌套内外层及同一外层参数中的实现；不同表达式的兄弟调用不自动成为必要证据。范围缺失时保守沿用全部 companion 范围，不能凭同一行推定嵌套。这只是语法包含关系，不宣称已解析跨语句数据流；模型仍须补读实质判断所缺实现。旧 v7 计划与证据义务保持原样。

漏引纠错在既有一次机会内，明确提交缺失的必要 ID、未覆盖范围及可见覆盖 ID；只列出同快照有效活动证据，不自动修改模型答案。纠错重用原预算、期限和 checkpoint。调查失败保留 failed，已启动但未有验收结果的调查保留 incomplete；未启动才是 not_executed。中文错误和前后端计数同步，不把失败转换为已回答或绿色结论。

## 系统性稳定化（本轮）

新建任务冻结 review-stability-v2；v1 及无契约任务继续原行为。主检查的纠错给出相对本次引用的未覆盖区间、侧别及可用证据；纠错只接收被拒分量，不再次派生已接受的候选或线索。调查在一次纠错后仍只有引用覆盖错误、且完整有效证据确实可见时，由服务端保存 citation_coverage_incomplete 未决结果和原拒绝记录；不采用原肯定答案，不关闭实质未决，不降级越权、快照冲突或未知发送。

同输入完整结果默认复用，前端允许强制全新审查。复用包括已确认发现、核验/发布依据、调查与覆盖，并保留来源，不凭零发现筛选来源；跨提交仍执行原重验规则。未完成任务的续查复用原检查点，原预算和期限不重置，界面明确恢复资格；超期或未知发送提供全新审查入口，不伪造自动恢复。

v2 调度冻结本轮领取的工作项，按领取顺序预留请求；成功响应在全部首轮请求完成准入后才结算，按固定顺序应用，再统一派生。网络调用保留配置并发上限，不能用完成顺序抢占派生名额；不等待全部初始 inspect 最终完成，因此 blocked 主检查仍能获得调查补证。原始响应和账本继续先落盘，恢复沿原响应重放机制处理未知发送，不承诺重发获得相同模型回答。初始检查按当时请求估算预留一次调用和输入输出 Token，其他工作项不能占用这部分；实际请求增长或费用上限仍可能拒绝，不能将保护估算写成完成保证。未发送释放时恢复保护，已发送未知消费不退还，所有者结束后释放剩余保护。

辅助预装载与必要引用分离。局部变量的一跳使用只用于同函数、直线单次赋值的辅助源码准备，不证明绑定或数据流完整；多语言先补变更完整定义、同文件直接定义和导入上下文，不提升语法提示为 resolved。必要内外层实现继续严格验收。重复候选先在纠错入口防重复；不在编辑摘要阶段合并权威事实，不按同一行号删除不同机制的问题。

预览/确认入口默认选择最新的兼容来源，不按发现数量挑绿色记录。完整同快照结果优先提供“查看已保存结果”，包含历史讨论时明确沿用保存时的讨论，不能假装刷新了讨论。可执行的结果复用继续满足增量绑定与发布依据校验；包含历史讨论的新执行仍需重验讨论。低层无预览创建接口保留独立完整运行语义，不凭 Head 猜测有效 Base、配置和输入。`force_full_review` 进入预览作业、确认指纹与创建请求；修改后必须更新方案。

`POST /reviews/{id}/resume` 使用新预览凭据，实时核对完整 PR 身份、背景、当前配置和有效 Base/Head，再检查原检查点、未知请求、累计调用/Token/费用与原期限。任务重排、凭据消费与入队同事务，重复消费返回原任务；活动租约、配置变化、过期和未知发送拒绝，不重置账本或纠错次数。旧 v1 Unit retry 兼容保留；v2 界面重试先进入重新预览，再明确确认本次续查的缺口范围。

候选聚类仅在同一快照、同一主张/触发/影响/建议/位置/证据下忽略引用与读取请求的顺序和重复项。不同自然语言机制、不同缺证据请求仍分别核验，不使用模糊相似度吞并发现。

轮次栅栏同时约束成功结算、传输失败结算与同一请求的后续传输重试，避免快速失败先释放预留或抢占下一次调用。取消不等待应用栅栏，已发送且无法确认消费的请求仍进入未知预留。该顺序只约束相同模拟响应下的调度与准入，不保证供应商多次独立生成相同答案。
