# 同快照审查稳定性修复

## 生效范围

新建任务冻结 `review-stability-v1`、`risk-planner-v7`。历史任务保持原协议、参数与检查点，不自动升级，也不修改其已保存结论。

本次减少的是取证与结束路径中的不确定性，不保证不同模型审查产生逐字相同的报告。

## 主要行为

- 在模型调用前受控准备变更符号与直接实现的源码；具体关系调查同时要求同一调用方的必要直接定义，避免仅凭 `inner` 推断 `outer(inner(...))` 的结果。
- 补充源码仍经路径权限、固定 Head、原文和哈希校验；敏感路径、超容量、源码缺失不能被静默当作完整证据。
- 调查可返回结构化 `missing_evidence`。服务端至多进行两轮自动恢复，每轮至多四个范围，沿用当前读取行数上限、预算与期限；重复、失败或仍不足时保留限制。
- 调用或 Token 余额临近上限时要求只提交现有结果，拒绝新增检索和线索；必要缺口及待核验候选仍保留，不把零发现等同于完整审查。
- 未证明绑定的关系在调查准入前保留为尚未核验提示；已经准入的必要调查不能因预算或低置信度被降级。
- 新审查使用 `temperature=0`，实际参数与请求哈希一致；不发送未经确认支持的 seed。旧任务继续使用原参数。

## 恢复与复用

已有 Unit 重试 API 继续使用 `POST /api/reviews/{task_id}/units/{unit_id}/retry`。新契约可重开该 Unit 的未决调查，不仅限于初始未检查目标；保留已验收目标、累计消费、格式纠错次数和原期限。未知发送或未知消费不作为免费重试。

普通“重新审查”仍独立执行。需要显式复用同快照成功记录时，在预览请求中提供来源任务：

```json
{
  "pr_url": "https://github.com/owner/repo/pull/123",
  "reuse_review_id": "0123456789abcdef0123456789abcdef"
}
```

此处任务 ID 为格式示例，不是可用的项目记录。后台预览作业的 `request` 同样接受该字段；前端 API 客户端已提供可选参数，本次未新增界面按钮。

来源必须属于相同 PR、使用新契约且满足完整性、快照、模型、策略、PR 声明、依赖与计量校验。已确认问题或未决调查不能作为无问题缓存复用。预览明确说明没有重新执行哪些 Unit，运行时再次核对来源报告哈希、Git delta 和目标覆盖；沿用的调查与提示保留来源任务和 Head。

不新增全局成功缓存表，不默认复用历史绿色记录，不拼接不同失败任务的局部结果。部分失败优先在原任务的检查点中恢复。

## 验证边界

验证采用 SDK stub、临时开发测试仓库和持久化检查点，不调用真实模型、不执行被审查目标仓库代码、不改写运行数据库。

使用 PR #95 的历史产物离线重建关系规划：旧 v6 针对问题调用只要求两个源码范围，新 v7 要求三个，并包含完整外层 `weighted_posterior`。这验证取证范围修复，不代表真实模型已经完成重复稳定性评测。

修复前版本与当前版本对比的 24 组旧请求包（八个提示词版本、主审查/调查/讨论三种路径）保持逐字节相同。设计和实施记录见 [design.md](design.md)、[implement.md](implement.md)。
